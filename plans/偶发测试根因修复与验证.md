# 偶发测试根因修复与验证

关联问题：[#41](https://github.com/forestbat/DeepSeek-Harness-Sharp/issues/41)。

## 根因与触发

保留原分支的 19 个修复提交，并合并当前 `origin/master`，没有重新实现已合入的上游改动。

| 触发/相关用例 | 根因 | 修复 |
|---|---|---|
| `PtyDaemonSubscribeTests.Subscribe_StreamsSnapshotAndOutput`、`Subscribe_IsNonExclusive_TwoSubscribersSeeSameOutput`，输出块大于读缓冲后子进程空闲 | 本地与远程 PTY 先等待下一个 channel 元素，才处理当前块的未读尾部，标记被困在尾部 | 共用 `PtyOutputReader`，先排空尾部，再等下一块；组件测试覆盖小缓冲与 channel 关闭 |
| `Subscribe_CompletesWhenSessionExits`，输出泵 EOF 早于退出观察器 | EOF 与 `Exited` 状态之间新加入的订阅没有完成者 | 在订阅锁下记录输出泵已关闭，迟到订阅立即完成；退出测试由自己的命令触发退出，不再竞速固定 sleep |
| Windows 并发创建 PTY、`PtyDaemonTests.Start_ThenList_ContainsStartedSession` | ConPTY 创建过程临时替换进程级标准句柄，并发 park/restore 交错会让子进程继承测试进程的句柄而提前退出 | 标准句柄 park、CreateProcess、restore 作为同一临界区 |
| 停止 daemon 与下一次 accept 交错 | listener 已释放而 accept 仍被调用，释放阶段抛出异常 | 仅在停止取消已发生时结束 accept 循环，正常运行中的错误仍暴露 |
| `ChatWindowKeyBindingTests` 在 Windows 清理 home | models.dev 刷新是脱离窗口生命周期的后台任务，窗口释放后仍持有临时文件 | 窗口取消并等待刷新完成；取消的文件写入清理临时文件 |
| `JobsTests.PersistentBash.Timeout_ResetsShell`，Windows 冷启动/超时重建 shell | 命令时间预算把 shell 冷启动算在内，重建后的简单 echo 也被超时 | 收到命令开始标记后才启动命令预算；shell 启动有独立 30 秒上界；慢启动夹具覆盖启动长于命令预算但命令成功的情形 |
| `ChatWindowPaneTests.Remote_Pane_Runs_Command_Through_Real_Daemon_Pty`、真实 shell pane | 提示符未就绪就注入按键，且计数式短 delay 在 Windows 定时器粒度下超过用例总限时 | 先等待真实提示符，再输入；输出等待按墙钟截止，保留最后画面用于失败断言。总界限 30 秒覆盖提示符与命令两个各 10 秒的等待及创建/清理，不作为替代根因修复 |
| `PluginLifecycleTests`，观察终态与 settle 任务交错 | 状态已是 Disposed，而 settle 任务尚未完成，调用方提前返回 | 状态发布、任务替换/完成共用状态锁 |
| `ProjectMemoryTests.BuildIndex_TruncatesToBudgetKeepingPriority`，临时路径 GUID 含 `f29` | 对完整索引做裸子串否定断言，误匹配路径而非记录 | 断言完整的渲染记录前缀，并断言高优先级记录保留 |
| `SessionAutoRenameTests` 清理 checkpoint git 对象 | Windows 只读文件不能直接递归删除，局部清理逻辑未处理其属性 | 复用项目已有的 `TempTree` 路径与清理契约，删除重复清理代码 |
| `RemoteHostCapabilityTests.SessionsToolsFilesAndMessageFlowOverTheWire` | 测试后端在订阅创建前丢消息，sleep 不是订阅建立的同步屏障 | 后端从 session 创建开始记录事件，符合生产日志从 seq 0 重放的语义 |
| 远端审批/提问先于消费者枚举到达 | channel 延迟到枚举时创建，先到的通知被丢弃 | 连接实例创建时创建两个 channel；真实 TCP 回归先发送通知并等待同流 ping 屏障，再开始枚举 |
| 远端多次细粒度请求，在 TCP delayed ACK/Nagle 下累积延迟 | 帧头和载荷分别写入，触发小包等待 | 池化缓冲一次写完整帧；空帧和 Unicode 载荷回归断言恰好一次写入并从真实 codec 读回 |
| 完整 solution 构建后 `PluginTemplateTests` 与 `SettingsTemplateTests` 顺序/并发污染 | 模板插件模块初始化注册的全局 schema 在卸载后残留 | collectible ALC 卸载时只移除该次注册的快照；模板测试 finally 卸载并立即断言 schema 消失、模板仍同步；共享 registry 的测试使用同一 collection。测试工程显式构建模板插件，避免 CI 因模板不存在而跳过 |
| `BoardTests.Claim_ExpiresAfterTtl`、GUI token 统计在调度暂停下 | 用真实时间测试短 TTL/速率阈值 | 注入 `TimeProvider`，测试精确推进时间，不依赖线程调度速度 |
| 子代理结束与父代理返回竞速 | 结束通知由旁路任务发出，结果先完成 | 观察结果在结束通知发出后才完成 |
| ACP、MCP、host JSON-RPC 测试读半行 | 一边写 StringWriter，一边轮询完整文本，没有消息边界同步 | 共用按完整行发布的 `JsonRpcLineCapture` |
| transcript 滚轮测试在高负载下 | 连续事件触发的滚轮加速依赖墙钟间距，固定事件次数不保证到达目标行 | 每行一个 notch，以最小滚动量断言，不依赖加速 |

没有使用统一加长超时、失败重试或禁用用例来掩盖根因。
未删除既有实验资料、未跟踪的 `.omo/` 或 `packages`；没有本轮创建的过时诊断脚本需要保留。

## 验证方式

当前工具列表未提供 Rider MCP、`xdebug_*` 或 `rider_lint_files`，因此不能宣称做过 Rider/debugger 验证。
使用真实构建、编译器/分析器与测试运行器验证；所有本地 CPU 密集命令串行持有项目统一验证锁，构建使用 `-m:2`。

CI 在 Windows、Ubuntu、macOS 先运行完整 quick，再运行相关类连续三轮；`set -e` 使任意一轮失败立即失败，三轮不是失败重试。
macOS 沿用仓库已有的串行测试设置。
quick 排除 `GpuStress`、`OnlyGpu`、`RenderBench`、`LlmSmoke`，不把这些分类写成已通过。

验证结果以最终 PR 的当前 head checks 和实际运行结果为准。
