## web_fetch 安全边界

旧代理路径只检查非公网 IP 字面量，域名可绕开原有 DNS 公网校验。本次不以警告或文档代替修复：所有请求和重定向都经过现有公网地址解析策略，空答案、私网或混合公网/私网答案均拒绝。直连保持 socket 地址钉定；经代理时改写传输 RequestUri 为已校验的公网数字 IP，因此 HTTP 绝对 URI、CONNECT 和 SOCKS 的实际目标不再是可被二次解析的域名。原始 Host 保留，HTTPS 继续用原域名进行 SNI 与证书校验，不安装证书验证绕过回调。

.NET 10 的[连接键实现](https://github.com/dotnet/runtime/blob/v10.0.0/src/libraries/System.Net.Http/src/System/Net/Http/SocketsHttpHandler/HttpConnectionPoolManager.cs)分别使用 RequestUri 主机作为隧道目标、Host 作为 SSL 主机。测试不仅检查此实现依据，还检查代理实际收到的目标，并通过真实 HTTPS 转发验证正常证书校验可成功。

本机不控制代理的 DNS；该路径直接不请求代理解析目标域名。本机 DNS 不可用会明确失败，不回退到未校验域名。可信代理必须支持数字 IP 目标与原始 Host；恶意代理仍可无视所请求的地址，这是代理本身的信任边界。HTTP 无端到端机密性，HTTPS 保持正常证书保护。其他 HTTP/LLM 客户端仍按自身目标策略运行，不借此声称所有网络调用都有 web_fetch 的 SSRF 限制。

## 复现入口

先配置本机 .NET SDK 的 `DOTNET_ROOT` 与 PATH，再在仓库根运行：

```text
dotnet build DeepSeek-Harness-Sharp.slnx -m:2 -nodeReuse:false -p:UseSharedCompilation=false

tests/Dsh.Tests/bin/Debug/net10.0/Dsh.Tests -noColor -parallelMode none -method Dsh.Tests.OutboundProxyTests.* -method Dsh.Tests.OutboundProxyGuiTests.* -method Dsh.Tests.WebTests*
```

真实 smoke 使用隔离且已配置真实默认模型的 harness home，显式运行 `Dsh.Tests.OutboundProxySmokeTests`（`-explicit on`）；它在缺少真实配置时会失败，不假装通过。完整 quick 排除 GpuStress、OnlyGpu、RenderBench、LlmSmoke，在私有 Xvfb 中运行，并将测试进程既有 `DSH_HOME` 设置为当前 worktree 内短的唯一 ignored daemon 根，使用当前构建的 dsharp，不复用用户默认 daemon。三平台最终 CI 结果与当前 head/实际 checkout merge SHA 的对应证据记录在 PR 的最终验收评论，不以旧 head 的绿灯充当当前结果。
